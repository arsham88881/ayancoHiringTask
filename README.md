## روش اجرای پروژه

### پیش‌نیازها

- .NET SDK (نسخه مورد نیاز پروژه)
- یک IDE مانند Visual Studio
- نصب بودن `Serilog.Seq` (به‌صورت executable) روی سیستم برای مشاهده داشبورد لاگ‌ها

### مراحل اجرا

1. فایل پروژه با پسوند `src/.slx` را انتخاب کرده و پروژه را باز کنید.
2. روی **root solution** راست‌کلیک کرده و گزینه **Restore NuGet Packages** را انتخاب کنید.
3. پس از اتمام restore، کافی است روی پروژه موردنظر:
   - `Ctrl + F5` بزنید (اجرا بدون دیباگر)، یا
   - `F5` بزنید (اجرا با دیباگر).

### آدرس‌های Swagger

پس از اجرای پروژه، Swagger در آدرس‌های زیر در دسترس خواهد بود:

| سرویس | آدرس |
| --- | --- |
| تسک اصلی (Main Task) | `http://localhost:5142/swagger/index.html` |
| Fake API ها | `http://localhost:5152/swagger/index.html` |

### تست API اصلی

برای تست API اصلی می‌توانید از نمونه‌ی `curl` زیر استفاده کنید:

```bash
curl --request POST \
  --url http://localhost:5142/api/inquiries \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: 16885db9-ba6d-428e-aa21-54eb7e505b09' \
  --data '{
  "username": "arhs",
  "password": "2121",
  "plateNumber": "۱۳ٔن۵۴۰۵۳",
  "forceRefresh": false
}'
```

> **نکته:** هدر `Idempotency-Key` اجباری است و باید در هر درخواست توسط فرستنده ارسال شود. در صورت ارسال درخواست تکراری با همان کلید، از پردازش مجدد جلوگیری می‌شود.

## توضیح مختصر معماری

معماری استفاده‌شده در این پروژه صرفاً یک **Clean Architecture ساده** است و پیچیدگی خاصی ندارد. لایه‌ها به‌صورت زیر تفکیک شده‌اند:

```
├── Domain
├── Application
├── Infrastructure
└── Presentation (لایه اصلی / Main)
    ├── API اصلی (Main Task)
    └── Fake Provider API
```

- **Domain**: شامل موجودیت‌ها، قواعد و منطق دامنه.
- **Application**: شامل use case ها، سرویس‌های اپلیکیشن و قراردادها.
- **Infrastructure**: پیاده‌سازی ارتباط با دیتابیس و سرویس‌های خارجی.
- **Presentation (Main)**: شامل دو API مجزا:
  - یکی برای **Fake Provider ها**
  - یکی برای **تسک اصلی**

## تصمیمات مهم فنی

در این پروژه از تکنولوژی‌های درخواستی استفاده شده است، به‌علاوه‌ی کتابخانه‌های زیر:

| کتابخانه | دلیل استفاده |
| --- | --- |
| **Serilog** | ثبت و مدیریت لاگ‌ها |
| **Serilog.Seq** | نمایش داشبورد لاگ‌ها (پس از نصب exe روی سیستم، در آدرس `http://localhost:5341` قابل مشاهده است) |
| **Dapper** | برقراری ارتباط با دیتابیس |
| **RestSharp** | ارسال درخواست‌های HTTP |
| **Swagger** | نمایش بهتر و مستندسازی API ها |

### مدیریت Idempotency

برای مدیریت Idempotent (درخواست‌های هم‌زمان و تکراری):

- از هدر `Idempotency-Key` استفاده شده است که **باید در هر درخواست توسط فرستنده ارسال شود**.
- این مکانیزم از پردازش درخواست‌های تکراری جلوگیری می‌کند.
- پیاده‌سازی آن از طریق یک **Filter** و یک **Attribute** انجام شده است.

## فرضیات انجام تسک

فرضیات در نظر گرفته‌شده در زمان انجام پروژه به شرح زیر است:

1. در سیستم ما یک سری **استعلام** وجود دارد که یکی از آن‌ها می‌تواند **استعلام خلافی خودرو** باشد.
2. برای دریافت هر استعلام، می‌توانیم **چندین Provider** داشته باشیم.
3. هر Provider:
   - پیاده‌سازی مخصوص به خود را دارد.
   - دارای **اولویت صدا زدن** مخصوص به خود است.
   - این اولویت **قابل تنظیم** است.
